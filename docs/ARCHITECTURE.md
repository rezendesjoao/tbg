# TBG — Arquitetura e notas da API v14

## Decisões

| Decisão | Escolha | Por quê |
|---|---|---|
| Linguagem e build | JavaScript ESM puro, sem bundler; CSS puro | O Foundry carrega `import` nativo; `flags.hotReload` recarrega CSS, HBS e JSON sem F5 |
| Id, pasta e título | id `tbg`, pasta `tbg`, título `TBG` | O id precisa ser igual ao nome da pasta |
| Compatibilidade | `{ "minimum": "14", "verified": "14.367" }`, sem `maximum` | `maximum` é bloqueio duro; os recursos usados são exclusivos do v14 |
| Dependências | Nenhuma obrigatória. Sem libWrapper, sem socketlib | Menos atrito; tudo vem de hooks, `CONFIG` e eventos do core |
| Interface | ApplicationV2 + HandlebarsApplicationMixin; DialogV2; zero jQuery | AppV1 é removida no v16 |
| CSS | Layer `modules` (automática); variáveis `--tbg-*` | Vence o core sem `!important` |
| Balões | Uma faixa só, `#tbg-bubbles`, filha de `body`, com `position: fixed`, escalada pelo `--ui-scale` e com o `z-index` do canvas: acima do mapa, abaixo do HUD, das colunas da interface e das janelas. Todo balão (fala de token, uso da ficha, narração, conversa sem token) nasce na mesma linha, a *Altura da faixa* (`bubbleBandHeight`, 200 no padrão) pixels do topo, nunca abaixo do meio da tela; o x é o do token na hora da fala, ou o meio da parte visível sem token, e o balão nasce inteiro entre `ui.controls`/`ui.nav` e `ui.sidebar`. Core silenciado com `options.chatBubble = false` em `preCreateChatMessage` | Pedido do usuário (02/11/2026): os balões se sobrepunham, porque os de tokens em alturas diferentes subiam uns para dentro dos outros e os do meio da tela viviam numa camada à parte; ele pediu todos saindo de uma linha fixa no topo, com colisão entre eles, subindo aos pulos como no Habbo Hotel. `#ui-middle` só cobre 60% da largura, e dentro de `#hud` a linha fixa na tela teria de ser refeita a cada pan; num container fixo, só o x depende do mapa. A altura tem chave própria (0.16.1): a 0.16.0 reaproveitou a do antigo *Limite de subida*, que tinha outro sentido, e a mesa que o tinha aumentado (até 800) via os balões nascerem no pé da tela, atrás da barra de conversa |
| Pulos e colisão | Cada balão guarda `lift`, quanto já subiu, em pixels da faixa. `#settle()` desfaz sobreposições só subindo balões, de baixo para cima e o mais novo primeiro no empate; em free flow encostar é cruzar também na horizontal, linha a linha basta a altura (folga de 8 px). Um `setTimeout` encadeado, vivo só enquanto há balão, sobe todos uma linha (a altura do menor balão + 8 px) a cada `linha ÷ bubbleRiseSpeed` segundos, nunca antes de 700 ms depois do último nascimento; o narrador sobe só a cada N pulos, com N para levar 30 s até o topo sozinho. O y vai no `transform`, com transição de 200 ms (`--tbg-bubble-hop`), o x no `translate`, sem transição, e quem passa do topo esvanece | As posições só mudam em eventos (nascimento, pulo, pan, edição, remoção): nada roda a cada quadro e o pulo é composto na GPU. Subir só, na ordem certa, mantém o mais novo embaixo em cada coluna. Com transição no `translate`, o pan arrastaria os balões atrasados. O balão novo entra já pintado na linha, senão a transição o traria do topo. No Modo de Desempenho Baixo, com o movimento reduzido ou no modo fotossensível, o pulo é imediato |
| Pan e zoom | Hook `canvasPan`: o x de cada balão de token é refeito a partir de `canvas.stage` (pivô, escala e posição) e do desvio gravado ao nascer; o y nunca muda. Um zoom diferente do último roda `#settle()` | O core chama o hook antes de `hud.align()` e antes de o PIXI refazer as matrizes, então `worldTransform` ainda seria o do quadro anterior. O pan é translação pura e não cria sobreposição; o zoom muda as distâncias e pode encostar balões. O balão não segue o token que anda: fica onde a fala foi dita, como nas salas de bate-papo |
| Aba oculta | O estado de cada balão (`lift`, x) vive no JavaScript e a pintura grava o valor final no estilo; o pulo é transição CSS e a saída é agendada por `setTimeout` | Com a aba oculta o navegador suspende os quadros e as transições, e os temporizadores ficam mais lentos: ao voltar, cada balão já está no lugar certo, sem empurrão pela metade nem balões nascidos uns sobre os outros |
| Falante | Nativo intocado (`ChatMessage.getSpeaker`); texto sem comando é sempre fala, qualquer que seja `core.messageMode` | Atende "clicou no boneco, fala como ele". Sem o campo do chat, os botões de modo de mensagem só escolhem a privacidade das rolagens: uma fala que virasse sussurro ao Mestre porque a última rolagem foi privada seria um susto |
| Modo Narrador | O Mestre sem token nem personagem sempre narra; o interruptor (setting de cliente `narratorActive`, pelo retrato da barra de conversa ou Alt+N, com `tbg.narratorChanged`) estende a narração a quando há falante. `isNarrating(speaker)` decide, no hook `chatMessage`, no retrato da barra e no selo de digitação | Um modo custom em `CONFIG.ChatMessage.modes` fica gravado em `core.messageMode`; se o módulo for desativado, `ChatMessage.applyMode` quebra ao ler `cfg.handler` de um modo inexistente e nenhuma mensagem é criada. O botão saiu de `#message-modes` junto com o campo do chat |
| Comandos | `ChatLog.CHAT_COMMANDS`. O fora do personagem é o `tbgOff`, com a regex `^\[([^[\]]*[^[\]\s][^[\]]*)\]$\|^([^]*\S)\s*\[\]$` (a mensagem inteira entre colchetes, ou terminada em `[]`), cuja `fn` chama a do `ooc` com o texto sem os colchetes; o `= texto =` é o `tbgNarrateMarks`, com a regex `^=\s*([^=][^]*?)\s*=$` e o mesmo `narrate()` do `/n` | API oficial do v14; `MESSAGE_PATTERNS` some no v16. A `fn` do `ooc` (`#processChatCommand`) tira o falante e põe o estilo OOC, e o envoltório dela guarda o token do balão: os colchetes saem como o `/ooc` do core, que segue igual, sem código próprio. Só a mensagem inteira vira fora do personagem (pedido do usuário, 0.15.0, no lugar do `/off`): colchetes no meio da fala ficam como texto, e a rolagem embutida `[[1d20]]` não casa, porque o miolo não pode ter colchete. Passar pelo `narrate()` dá ao `= texto =` a mesma trava do `/n`: só o Mestre narra |
| Barra de conversa (D7) | `<input type="text">` próprio, montado no `ready` como primeiro filho de `#ui-bottom`, de `templates/chat-bar.hbs`; envia por `ui.chat.processMessage` com só `&`, `<` e `>` escapados; Enter, Shift+Enter (vira `/shout`), Esc e as setas tratados no `keydown` do campo, com `stopPropagation`; atalho `focusChatBar` (Enter) | O input simples dispensa o ProseMirror: uma linha, sem formatação, como as salas de bate-papo dos jogos. `#ui-bottom` é uma coluna flex que alinha embaixo e ao centro: primeiro filho, a barra fica acima da barra de macros e do HUD da Eternia, que se põe antes de `#hotbar`. Passar por `processMessage` mantém os comandos do core e do TBG e o hook `chatMessage` de outros módulos. O `KeyboardManager` do core escuta o `keydown` na janela, na fase de borbulha, e só ignora atalhos enquanto há campo focado: sem `stopPropagation`, o Esc que tira o foco seguiria até o atalho do core e soltaria o token. O `/w` do core lê `[Nome Composto]` ou uma palavra, nunca aspas |
| Dados | `flags.tbg.*` em ChatMessage (`kind`, `speaker`) | O Foundry sincroniza flags sozinho |
| Socket | `module.tbg` só para efêmeros | Nada persistente por socket |
| Medidas do balão | Fonte 16 px, altura de linha 1,25, preenchimento 2 px × 7 px, borda de 1 px e raio de 6 px, tudo em variáveis `--tbg-bubble-*`; retrato num quadrado escuro de cantos arredondados, encostado na borda esquerda | Balão colado no texto: a fala pesa mais que a moldura. Variáveis para ajustar sem mexer nas regras |
| Cabeçalho do balão | Retrato e `Nome:` em linha com a fala; a fala num `span` próprio | Balão mais compacto, no formato `**Nome:** texto`. O `span` separado deixa a edição da mensagem trocar só a fala |
| Linha única | `white-space: nowrap` no `.tbg-bubble`, sem largura máxima. Os blocos que o editor do chat cria (parágrafo, lista, citação, título) viram `display: contents` com um espaço no `::after`, e `<br>` e `<hr>` somem. Todo balão se centra no seu x pelo `translate: calc(x - 50%) -100%`, que também põe a base dele na linha | Pedido do usuário (12/10/2026): o balão nunca quebra, por mais longa que seja a fala, e cresce por igual para os dois lados; o limite de caracteres (130 desde a 0.14.1) mantém a linha legível. As regras de entrada do ProseMirror transformam `- `, `1. `, `> ` e `# ` no começo da mensagem em lista, citação e título, e colar texto de várias linhas cria parágrafos: como blocos, cada um abriria uma linha. `display: contents` tira caixa, margem e marcador sem perder o texto, e o espaço que sobra no fim da linha o próprio CSS descarta. Um `<br>` só chega por HTML colado e o CSS não o troca por espaço, então as palavras em volta se juntam. Sem quebra, a setting `bubbleMaxWidth` perdeu a função e saiu |
| Retrato no cartão | O TBG sempre insere o seu e o CSS o esconde com `:has(.message-header img)` quando o sistema já desenhou um | Sistemas como o dnd5e inserem o avatar em `renderChatMessageHTML` depois do nosso hook, então nenhuma checagem em JavaScript no momento do hook enxerga o avatar deles |
| Limite de caracteres | Constante `CHAT_MAX_LENGTH` (130, desde a 0.14.1; era 100) em `constants.mjs`, aplicada no `beforeinput` da barra (recusa a inserção inteira que passaria do limite) e no `maxlength` do campo | Recusar a inserção inteira cobre digitação e colagem sem truncar texto pelas costas do usuário; o `maxlength` cobre a composição de acentos, que o `beforeinput` não pode cancelar. Não é setting porque o Foundry só usa o padrão de uma setting quando o mundo nunca a gravou, e a tela de configurações grava todas ao salvar: o limite acabava congelado no valor antigo de cada mundo. Apagar sempre passa |
| Digitação | Socket `module.tbg` com reenvio a cada segundo enquanto o texto muda, fim explícito após três segundos sem mudança ou ao perder o foco, expiração de quatro segundos no destinatário e eco local em quem digita; o falante anunciado fica guardado e, narrando, não há falante | Texto parado no campo não é digitação. A expiração só cobre pacote perdido ou cliente que caiu. O eco local é necessário porque `game.socket.emit` não devolve o pacote a quem enviou. Guardar o falante encerra o selo certo quando se troca de token no meio |
| Selo de digitação | Classe própria, montada por DOM de forma síncrona em `#tbg-typing-indicators`, dentro de `#hud`, posicionada em coordenadas de mundo dentro da arte do token e dimensionada como fração do token; acompanha o token pelo `refreshToken` | Preso ao token, precisa encolher e crescer com o mapa; usar a escala de tela dos balões o faria transbordar o token quando afastado. Com template assíncrono, um `hide` que chegasse antes do elemento existir deixava um selo órfão |
| Ação na fala | `*texto*`, `**texto**` ou `'texto'` viram `<strong>` em toda conversa, no `preCreateChatMessage` (`chat/marks.mjs`), só nos nós de texto: a marca abre no começo ou depois do que não é letra nem número e fecha antes do mesmo. O `emote` do core (`/me`) é envolvido em `CHAT_COMMANDS`: o conteúdo vira o texto limpo de `match[2]` dentro de `<strong>`, com tipo `say` e estilo IC. A exportação do histórico devolve os asteriscos | Pedido do usuário (0.15.0, no lugar do comando `*texto*` de mensagem inteira e do balão bege): a ação combina com a fala, no balão comum, só em negrito. No `preCreate`, a regra vale para todo caminho (fala, grito, sussurro do core, pensamento, narração, `/ooc`) sem embrulhar cada comando; os nós de texto protegem tags e atributos, e as fronteiras deixam em paz o apóstrofo de "d'água" e a conta "2*3". O `/me` do core punha o nome no começo do texto, que o balão já mostra. O tipo `action` só existe em mensagens antigas e no estilo emote sem flag, e se desenha como ação inteira: o balão comum com o texto em negrito |
| Contador | No fim da barra, `n/130`, interpolando de `--tbg-char-count-base` até `--tbg-char-count-peak` com `color-mix` guiado por `--tbg-char-ratio` da metade do limite em diante | Dentro da barra, sobre fundo próprio, não precisa mais do contorno que o deixava legível sobre o chat |
| Visibilidade | Balões sobre token e balões do narrador exigem `message.isContentVisible` | `visible` é verdadeiro para todos num sussurro com rolagem, e o servidor manda toda mensagem a todo cliente; `isContentVisible` também esconde a mensagem cega do próprio autor, como o `???` do log |
| Balão de fala | Só para `isSpeech(message)`: comando do TBG, ou tipo `base` em IC/EMOTE, sem rolagem | Cartões de sistema sussurrados viravam balão de sussurro com o HTML do cartão (vazio no dnd5e 6, que renderiza o cartão depois). Um cartão de tipo `base` criado no modo em personagem continua indistinguível de uma fala criada por macro, e segue virando balão se não for reconhecido como uso |
| Uso da ficha | Resolvedor genérico em `chat/usage-item.mjs`: varre `system`, as flags de outros pacotes e as opções das rolagens; depois atributos `data-item-*`; depois títulos visíveis. Só aceita item do ator falante, de `ChatMessage.getSpeakerActor` | Core não tem hook de item usado e cada sistema guarda o item num lugar (dnd5e 6 em `system.item`, PF2e em `flags.pf2e.origin`, Daggerheart em `system.source.item`, OP RPG em `flags.dnd5e.item` e `data-item-id`). Ler os dados sem chave de sistema não prende a nenhum schema. `message.speakerActor` cai para `author.character`. Exigir o dono barra o item do conjurador numa salvaguarda rolada pelo alvo; um id recusado como UUID não volta como id solto, porque o ator sintético tem os ids de item do base |
| Rótulo do uso | Nome do item; sem item e com rolagem, a flag `core.initiativeRoll`, o primeiro título do `flavor`, a primeira linha dele ou `roll.options.flavor`; sem rótulo, nada | Nunca o resultado nem a fórmula: a D2 (balão de dado) segue vetada, e um `/roll 1d20` cru não é ação da ficha |
| Deduplicação do uso | Sem estado: a mensagem que referencia, em qualquer string de 16 caracteres, um uso anterior do mesmo `actor.uuid` não gera balão; nem o mesmo uso repetido em 1,5 s. Só contam usos cujo conteúdo este cliente vê | Um clique no dnd5e gera cartão, ataque e dano ligados por `system.origin`. Lendo só `game.messages`, o F5 não repete. Clientes podem divergir de propósito: um cartão privado não cala, para os jogadores, a rolagem pública que o segue. `actor.uuid` porque tokens não vinculados compartilham o id do ator base |
| Nome no uso | O alias do falante quando difere do nome do ator; senão o nome do token. Token que o cliente não vê não ganha balão | O alias escolhido de propósito (combatente renomeado, macro que fala como "???") é o que o autor quis mostrar; o alias igual ao nome do ator é só o padrão do sistema e revelaria um NPC disfarçado. Um balão escondido ainda empurraria os vizinhos e denunciaria onde o token está. Sistemas que gravam só o ator caem no único token dele na cena |
| Balão do narrador | A marcação do `.tbg-bubble` com a variante `.tbg-bubble--narration` (fundo preto, letras brancas e, pelo `portraitIcon` do `bubble.hbs`, um pergaminho branco no lugar do retrato), na faixa como todo balão, no meio da parte visível; sobe a cada N pulos e fica pelo menos 30 s (`NARRATION_MIN_MS`) mesmo com um `bubbleMaxLifetime` menor | Reaproveitar a marcação e o CSS dos balões dá o mesmo formato e tamanho dos balões dos jogadores sem duplicar regras; a variante só troca as cores. A narração precisa de meio minuto na tela (pedido da 0.15.0); no ritmo dos outros, sozinha, sairia em uns 20 s. Pular menos vezes, sempre junto com os outros, mantém o compasso, e quem estiver embaixo dela ainda a empurra, então ela nunca sobrepõe ninguém. Funciona sem cena: a faixa não depende do canvas |
| Chat lateral só com rolagens | `isTalk` (`chat/kinds.mjs`) separa a conversa (fala, narração, OOC digitado, sussurro digitado sem falante) do resto. No `preCreateChatMessage`, a conversa recebe `options.notify = false`; no `renderChatMessageHTML`, a classe `tbg-talk`, que o CSS esconde; e o CSS esconde `#chat-message` | As opções do `preCreateChatMessage` viajam para os outros clientes, e `ChatMessage#_onCreate` chama `ui.chat.postOne(this, {notify: options.notify ?? true})`: sem notificar, a conversa não vira notificação no canto nem acende o aviso da aba. Ela ainda entra no log (o `postOne` e o lote de abertura renderizam toda mensagem `visible`), então quem a esconde é a classe. Mexer em `visible` não serve: `isContentVisible` termina em `return this.visible`. Os botões de `#message-modes` ficam, porque escolhem a privacidade das rolagens. As abas ON, OFF e ROLL (C2) saíram |
| Guia do jogador (D8) | Botão de `registerMenu` que abre um `DialogV2` próprio; o guia é um `JournalEntry` marcado com a flag `guide`, gerado de `templates/guide/*.hbs` com o limite de caracteres, o nome do narrador e o atalho da mesa; páginas do Mestre com `ownership.default = NONE` | O jogo por texto precisa de um material que a mesa leia no próprio Foundry. Diário no mundo, e não compêndio, por escolha do usuário: dispensa o build de LevelDB. Recriar troca só as páginas, então pasta, permissões e links para o diário continuam. Os exemplos usam a marcação e o CSS reais dos balões, então o guia mostra o visual atual |
| Histórico da cena (A8) | `SceneHistory` (ApplicationV2 + Handlebars, `templates/history.hbs`), id `tbg-history`, aberta pela ferramenta `tbgHistory` dos tokens com `order` = o do `eterniaMarket` + 0,5 quando ele existe; lista as 500 últimas conversas com `isContentVisible` do recorte (o jogador: a cena vista desde `flags.tbg.talkSince`; o Mestre: a cena vista inteira ou todas, com uma faixa por cena), redesenha por `createChatMessage`, `updateChatMessage`, `deleteChatMessage`, `canvasReady` e a mudança de `talkSince` (com espera de 80 ms) e guarda o texto enriquecido por mensagem; o Mestre exporta o recorte inteiro em JSON por `foundry.utils.saveDataToFile` | O `SceneControls` do v14 ordena as ferramentas por `order` numérico, então meio ponto põe o botão logo abaixo do Mercado sem conhecer a Eternia além do nome da ferramenta. A exportação existe para ler a campanha fora do Foundry (o mundo da mesa fica numa VPS). Ler `game.messages` em vez de guardar uma cópia faz o F5 e quem entra depois verem o mesmo histórico. Descer sozinho só quando já estava no fim deixa quem subiu para reler onde parou. Na Eternia a janela ganha o pergaminho pela lista `THEMED` de `module/apps/window-theme.mjs` |
| Cena da conversa e o recomeço | `flags.tbg.scene` gravada no `preCreateChatMessage` (a do falante, a do token do balão ou a cena vista); ao `updateScene` com `active: true`, o Mestre ativo (`game.users.activeGM`) grava na cena `flags.tbg.talkSince` com o `Date.now()` dele menos 5 s. Nada é apagado | Pedido do usuário (0.15.0): o histórico recomeça a cada cena para os jogadores, mas o Mestre guarda tudo. O `timestamp` de cada mensagem é o relógio de quem a criou, então a folga cobre a diferença entre os relógios; o `game.time.serverTime` do v14 conta desde que o servidor subiu e não se compara com ele. Mensagens antigas sem a flag caem na cena do falante ou do token do balão. Na 0.14 a troca de cena apagava a conversa das outras cenas |
| Aviso do Mestre | `confirmSpeaker` (`chat/guard.mjs`), chamado pela barra antes de enviar: para o Mestre, se o comando fala pelo token selecionado (texto sem narrar, com ou sem ação, `/say`, `/shout`, `/think`, `/me`, `/ic`, `/w`) e o ator tem jogador (dono ou personagem atribuído), um `DialogV2.wait` com Cancelar como padrão; a caixinha guarda o uuid do ator até recarregar | Pedido do usuário (0.15.0): o Mestre quase nunca fala pelo personagem de um jogador, e com vários tokens na mão é fácil errar. Na barra, e não no hook `chatMessage`, porque o hook não espera uma pergunta; o texto fica no campo até a resposta. Macros que chamam `processMessage` não perguntam |
| Mestre sem token | O texto sem comando vira narração (o hook do narrador roda antes do da fala); os comandos sem token (`/shout`, `/w`) passam por `isMasterVoice` (autor Mestre, sem ator, token nem token de balão, e não narração): o balão do meio da tela sai sem nome e o histórico mostra "Mestre" | Pedido do usuário (0.14.1): sem token selecionado, o Modo Narrador fica sempre ativo. Na 0.14.0 o texto saía num balão padrão sem nome, que continua para os comandos |
| Conversa sem token | A conversa da cena vista cujo falante não tem token nela (setting `enabled` e o `chatBubbles` do core) nasce no meio da faixa, com o visual do tipo de fala; a voz do Mestre (`isMasterVoice`) sai sem nome. Fala de token que este cliente não vê não ganha balão | Sem token não há x de onde nascer, e o meio é o lugar do narrador. Uma fala cujo token está na cena nunca vai para o meio, mesmo que o cliente não o veja: lá ela denunciaria quem está escondido. Na faixa, o balão de um token escondido abriria um buraco e empurraria os vizinhos, então ele não nasce, como já era com o balão de uso |
| Migração | Setting de mundo `migration` (versão 1), aplicada uma vez pelo Mestre ativo no `ready`: a `bubbleRiseSpeed` gravada em 35 vira o padrão novo (15) e, com o Custom Chat Tabs ativo e as abas ligadas, um `DialogV2.confirm` oferece desligá-las | O Foundry só usa o padrão de uma setting que o mundo nunca gravou: sem migrar, a mesa que já salvou as configurações continuaria a 35 |
| i18n | `lang/pt-BR.json` e `lang/en.json`, chaves `TBG.*` | pt-BR é o público principal |

## Estrutura

```
scripts/
  tbg.mjs            entrada: init e ready; chama os register…() de cada domínio
  constants.mjs      MODULE_ID, KINDS, BUBBLE_KINDS, SOCKET_EVENT, TEMPLATES
  utils.mjs          log, warn, debug, localize, stripParagraph
  settings.mjs       tabela de settings e registerSettings()
  sockets.mjs        socket module.tbg e CONFIG.queries
  api.mjs            game.modules.get("tbg").api
  migration.mjs      migração única do mundo: velocidade de subida e abas do Custom Chat Tabs
  chat/
    kinds.mjs        resolveKind, isSpeech, isTalk e isMasterVoice
    speaker.mjs      speakerToken(message), actorToken(actor), speakerImage(message)
    commands.mjs     /say /shout /think /n, = texto =, [texto] fora do personagem, /me como ação, texto simples como fala e o falante de sussurros
    marks.mjs        *ação* e 'ação' em negrito em toda conversa
    bar.mjs          ChatBar: a barra de conversa, teclas, limite, contador, quem fala e o atalho Enter
    log.mjs          marca a conversa no chat lateral para o CSS esconder
    typing.mjs       TypingAnnouncer: socket do indicador, ociosidade, foco e eco local
    usage.mjs        resolveUsage(message) e isRepeatedUsage(message, usage)
    usage-item.mjs   usedItem(message, actor): o item do falante, sem chave de sistema
    narrator.mjs     interruptor, atalho e dados de narração
    render.mjs       tema dos cartões de rolagem: classes, retrato
  history/
    scene.mjs        talkScene, isCurrentScene, a cena gravada na conversa e a limpeza ao ativar outra cena
    window.mjs       SceneHistory: a janela do histórico, o botão dos tokens e o que a mantém em dia
  guide/
    guide.mjs        writeGuide(): cria ou atualiza o diário "Guia do TBG"
```

## Fluxos

**Balão (A1).** `createChatMessage` dispara em todos os clientes → `BubbleLayer.onMessage` descarta mensagens cujo conteúdo o cliente não vê, manda a narração para o meio da faixa, desvia para o balão de uso (A9) o que for ação da ficha e, do resto, aceita a fala com tipo que tem balão de um token da cena atual que o cliente vê (ou a conversa sem token, para o meio) → enriquece o conteúdo com `TextEditor.enrichHTML` (segredos só para dono ou GM) → renderiza `templates/bubble.hbs`, pinta o balão na linha de nascimento, no x do token, e o anexa em `#tbg-bubbles` → mede e encosta o balão na parte visível → `#settle()` sobe os que ele encosta (free flow) ou todos os que estão na linha dele (linha a linha), em cadeia → a cada pulo do cronômetro, todos sobem uma linha juntos (o narrador, a cada N pulos), `#settle()` corrige quem encostou e quem passou do topo esvanece; o *Tempo máximo* tira o balão onde ele estiver → o `canvasPan` leva os balões de token junto na horizontal.

Escala: em `screen` o balão recebe `transform: scale(1/zoom)` com origem no centro inferior, ficando do mesmo tamanho na tela em qualquer zoom; em `world` ele escala com o mapa como o balão do core.

**Barra de conversa (D7).** O `keydown` do campo trata Enter (envia; com Shift, antes de `/shout`), Esc (tira o foco) e as setas (as 20 últimas mensagens, mais o rascunho); o `beforeinput` recusa o que passaria do limite; o `input` atualiza o contador e dispara `tbg.chatInputChanged` para o selo de digitação, e o `blur`, `tbg.chatInputBlurred`. Enviar esvazia o campo na hora e chama `ui.chat.processMessage`; se o envio falha, o texto volta. O retrato acompanha `controlToken`, `canvasReady`, `updateUser`, `updateToken` do token controlado e `tbg.narratorChanged`.

**Modos de fala (A3).** `/say`, `/shout`, `/think`, `/n`, `= texto =` e os colchetes do fora do personagem são entradas em `ChatLog.CHAT_COMMANDS`; cada uma grava `flags.tbg.kind`. `/n` e `= texto =` (`tbgNarrateMarks`) chamam o mesmo `narrate()`, que recusa quem não é Mestre com o aviso `TBG.Errors.narratorGMOnly`. O `[texto]` e o `texto []` (`tbgOff`) passam pelo `ooc` do core, já envolvido para guardar o token do balão em `flags.tbg.bubbleToken`, com o texto sem os colchetes. A ação entre asteriscos ou aspas simples não é comando: o `preCreateChatMessage` de `chat/marks.mjs` a troca por negrito em qualquer conversa. O hook `chatMessage` trata todo texto sem comando como fala, qualquer que seja o modo de mensagem: com falante (token selecionado ou personagem atribuído), em personagem (`kind: say`, modo `ic`); sem falante, fora do personagem (`kind: ooc`, modo `public`) para o jogador, e a voz do Mestre para o Mestre. No v14 o modo "Public as User" transformaria o texto simples em OOC mesmo com token selecionado, e os modos privados o transformariam em sussurro. `/me` e `/w` são do core: o `/me` envolvido vira uma fala com o texto inteiro em negrito; para `/w`, o hook `chatMessage` guarda o falante em `flags.tbg.speaker` (o core o apaga em sussurros) e `preCreateChatMessage` o restaura quando há token, para o sussurro sair em personagem e virar balão só para quem recebe.

**Narrador (B1).** O Mestre narra sem falante e, com a setting de cliente `narratorActive` (alternada pelo retrato da barra ou por Alt+N), também com falante: o hook `chatMessage`, registrado antes do da fala, intercepta texto sem comando, cria a mensagem com `speaker.alias` = nome do narrador, estilo OTHER e `flags.tbg.kind = "narration"`, e retorna `false`. Sem token no falante, não há balão sobre token; a narração vira o balão do narrador (B8). Comandos (`/roll`, `/w`, `[texto]`) passam direto para o core; a ação entre asteriscos é texto e entra na narração, em negrito. Narrando, o selo de digitação não aparece.

**Narração e conversa sem token (B8).** `createChatMessage` com `isContentVisible` e ou `resolveKind === "narration"` (com a setting `narrationBanner`), ou conversa da cena vista sem token do falante nela → o balão nasce no meio da parte visível da faixa, na mesma linha dos outros, e colide com todos como qualquer balão; a narração leva o nome e o pergaminho do narrador, pula a cada N pulos e fica pelo menos 30 s, e a voz do Mestre sai sem nome. Editar a mensagem troca o texto e roda `#settle()`. Apagar a mensagem esvanece o balão.

**Uso da ficha (A9).** Para mensagem sem `flags.tbg.kind` e com ator falante, `resolveUsage` procura o item do ator e, sem item, o rótulo da rolagem. Havendo resultado, `BubbleLayer` acha o token (o do falante; sem token no falante, o único token do ator na cena), descarta token que o cliente não vê e repetição (`isRepeatedUsage`) e mostra o balão bege `USAGE_KIND` "Nome usou X" ou "Nome rolou X", com a imagem do item ou um dado. Updates da mensagem não mexem nesse balão.

**Tema do chat (C1).** `renderChatMessageHTML` adiciona aos cartões que não são conversa `tbg-message`, `tbg-kind-*`, `tbg-roll`, a variável `--tbg-author-color` e o retrato do falante. O agrupamento de falas seguidas saiu com elas.

**Histórico da cena (A8).** A ferramenta `tbgHistory` alterna a `SceneHistory`. O contexto lê `game.messages`, filtra `isTalk`, `isContentVisible` e o recorte (jogador: cena vista desde `talkSince`; Mestre: a cena inteira, ou todas), guarda as 500 últimas e monta cada linha (hora, retrato ou ícone, nome ou "Mestre", a nota de sussurro, pensamento ou fora do personagem, o texto enriquecido e o token, se ele está na cena e visível). O `_preRender` anota se o log estava no fim; o `_onRender` desce até o fim nesse caso. O `updateScene` com `active: true` faz o Mestre ativo gravar `talkSince` na cena, e o `canvasReady` e essa gravação redesenham a janela. O botão de exportar baixa o recorte inteiro, sem o teto de linhas.

## Notas da API v14 (lidas no fonte 14.367)

- `ChatLog.parse(message)` itera `CHAT_COMMANDS` em ordem de inserção sobre o HTML sem o `<p>` externo; sem comando devolve `"none"`. `processMessage` chama o hook `chatMessage(chatLog, message, chatData)` antes do parse e aborta se ele retornar `false`.
- `ChatMessage#_preCreate` aplica `options.messageMode` e define `options.chatBubble ??= mode === "ic"`; `_onCreate` chama `ui.chat.postOne(this, {notify: options.notify ?? true})` e `game.messages.sayBubble` só se `options.chatBubble` for verdadeiro. O hook `preCreateChatMessage` roda no cliente que cria e suas mudanças em `options` viajam para os outros clientes.
- `ChatBubbles#say` limpa `.chat-bubble[data-token-id]`, enriquece o texto, chama `chatBubbleHTML(token, html, message, options)` e cancela se o hook retornar `false`. Container do core: `#chat-bubbles` dentro de `#hud`.
- `#hud` recebe `width/height` do canvas, `left/top` de `canvas.primary.getGlobalPosition()` e `transform: scale(zoom)` com `transform-origin: top left`; `#hud > *` é `position: absolute`. O HUD é renderizado a cada `Canvas#draw` (`renderHeadsUpDisplayContainer`) e seu `innerHTML` é substituído.
- Durante a animação de movimento, `Token#_onAnimationUpdate` grava a posição interpolada em `token.document` (`mergeObject(this.document, animationData)`), então `token.center` e `token.document.y` acompanham o movimento; a posição PIXI `token.y` do container não é confiável.
- O input do chat é um `<prose-mirror id="chat-message">`; `value` devolve o HTML serializado, mas `value = ""` não limpa um editor ativo. O elemento dispara o evento `plugins`, o `ChatLog` adiciona `chatInput`, `keyMaps` e `menu`, e `ProseMirrorEditor.create` mescla tudo sobre os defaults com `Object.assign({}, defaults, plugins)` antes de chamar `Hooks.callAll("createProseMirrorEditor", uuid, plugins, options)`; `Object.values(plugins)` define a ordem em que `handleKeyDown` roda.
- `core.messageMode` é `StringField` sem `choices`; `#message-modes` é montado uma vez em `ChatLog#renderNotifications` a partir de `CONFIG.ChatMessage.modes` e re-parentado entre sidebar, popout e overlay (`renderChatInput` entrega `#message-modes`, `#chat-message`, `#chat-controls`).
- `ChatMessage#renderHTML` gera `li.chat-message.message.flexcol` com classes `ic`, `emote`, `whisper`, `blind` e `borderColor` da cor do autor para OOC; template `templates/sidebar/chat-message.hbs`.
- `game.keybindings.register` só funciona no `init`. O `KeyboardManager` escuta `keydown` na janela, na fase de borbulha, e não processa atalhos enquanto `hasFocus` (campo de texto, `contenteditable` ou botão dentro de formulário).
- `#ui-bottom` (`templates/views/game.hbs`) é `flexcol` com `justify-content: flex-end` e `align-items: center`, dentro de `#ui-middle`, que tem `pointer-events: none`.
- O `/w` do core (`CHAT_COMMANDS.whisper`) aceita `[Nome Composto, Outro]` ou uma palavra; aspas não agrupam o nome.
- `ProseMirrorEditor.buildDefaultPlugins` põe `chatInput: new Plugin({})` em todo editor como reserva de ordem (`client/applications/ux/prosemirror-editor.mjs:311`); o do chat é trocado por `ChatInputPlugin.build(...)` em `ChatLog#_onConfigurePlugins`, que guarda a instância em `spec.instance`.
- `ChatMessage#visible` é verdadeiro para todos em sussurro com rolagem (`client/documents/chat-message.mjs:101-107`); `isContentVisible` (`:70-82`) é o portão de privacidade. `speakerActor` cai para `author.character`; `ChatMessage.getSpeakerActor(speaker)` não.
- `message.toObject().rolls` são strings JSON; as opções ficam em `message.rolls[i].options`. `foundry.utils.parseUuid(uuid).id` é o último segmento, não o id do item.
- ChatMessage tem campo `title` no v14; o dnd5e 6 grava "Item - Atividade" nele e deixa `content` vazio, renderizando o cartão depois do hook `renderChatMessageHTML`.
- `#ui-middle` é marcação estática de `templates/views/game.hbs`, com `transform: scale(var(--ui-scale))` e `z-index: var(--z-index-app)`; janelas começam em `--z-index-window` (100).
